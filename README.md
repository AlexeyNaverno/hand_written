# Почерк

Программа пишет любой текст вашим почерком. Буквы берутся с фотографии обычной рукописной страницы, складываются в библиотеку, и из них набирается текст с соединениями между буквами. Результат — PDF.

Вся обработка идёт на устройстве: фотографии, буквы и тексты никуда не отправляются. Сеть нужна один раз, чтобы скачать саму программу (в APK уже всё внутри).

## Как запустить

**Телефон на Android, приложение.** На странице Releases репозитория лежит сборка `pocherk.apk` («Почерк для Android: последняя сборка»). Скачайте файл на телефон и откройте; Android попросит разрешить установку из этого источника. Сборку делает GitHub Actions при каждом изменении.

**Телефон или компьютер, в браузере.** После включения GitHub Pages (Settings → Pages → Source → GitHub Actions) программа открывается по адресу `https://<пользователь>.github.io/hand_written/`. В Chrome на Android её можно установить через меню «Установить приложение»; дальше она работает без сети.

**Компьютер, из исходников.**

```bash
npm install
npm run model     # скачать модель распознавания (50 МБ) в public/models
npm run dev       # открыть http://localhost:5173
```

## Как пользоваться

1. **Сбор букв.** Сфотографируйте страницу своего рукописного текста. Программа найдёт строки и прочитает их. Исправьте ошибки чтения в поле под строкой и нажмите «Разобрать на буквы». Каждую вырезанную букву программа читает ещё раз отдельно: совпавшие с текстом отмечены зелёной рамкой и выбраны, остальные серые. Нажатие на букву меняет выбор, нажатие на подпись исправляет символ. Кнопка «В библиотеку» сохраняет выбранные.
2. **Библиотека.** Таблица показывает, сколько вариантов каждого символа собрано. Для живого почерка нужно по 3–5 вариантов буквы. Неудачный вариант можно выключить или удалить. Библиотеку можно сохранить в ZIP и загрузить обратно.
3. **Текст → PDF.** Введите текст, нажмите «Предпросмотр», затем «Сохранить PDF». «Проверить чтением» читает написанные слова распознавателем и показывает те, что не совпали с текстом.

### Какое нужно фото

- Одна страница на кадр, в полном разрешении камеры, без сжатия в мессенджере. Толщина штриха на снимке должна быть не меньше 5–6 пикселей: при 2–3 пикселях тонкие соединительные штрихи рвутся и буквы выходят размытыми.
- Ровный свет без теней, лист лежит плоско.
- Подходит обычная тетрадь в клетку или линейку и чистый лист. Линовка используется как подсказка и из букв убирается.
- Нужны и математические знаки, и знаки препинания: пишите в тексте `=`, `+`, цифры, скобки, кавычки, тогда они попадут в библиотеку.

### Правила набора

- Абзац — это текст до перевода строки. Абзац короче пяти слов, который умещается в одну строку и не кончается точкой или запятой, пишется как заголовок по центру. Условие про точку отключается в настройках. Работают и пометки старой программы: `**заголовок**` и `*подзаголовок*`.
- Нажим пера (толщина штриха) меняется только между абзацами. Заголовки пишутся чуть жирнее.
- Русские буквы соединяются, английские пишутся печатными и стоят отдельно, как цифры и знаки.
- Соединение ведётся пером по кривой от точки выхода одной буквы к точке входа следующей; на линии делается небольшой искусственный бугорок. Высота бугорка, неровность почерка и разница нажима настраиваются.
- Если символа нет в библиотеке, на его месте остаётся пробел, а программа перечисляет недостающие символы.

## Формат библиотеки

В ZIP лежит папка `symbols`: на каждый вариант буквы цветной PNG с прозрачным фоном и JSON. Имена файлов как в старой программе: `а_3.png`, `загл_б_1.png`, `точка_2.png`, цифры — `53.png`. Папку `symbols` старой программы можно загрузить как есть, недостающие поля будут оценены.

```json
{
  "schema": 2,
  "char": "и",
  "variant": 4,
  "position": "medial",
  "prev": "ш",
  "next": "р",
  "bbox": [3.2, 3.1, 40.5, 46.0],
  "baseline": 43.8,
  "x_height": 64.0,
  "stroke_width": 4.1,
  "slant": 0.5,
  "ink_rgb": [38, 52, 128],
  "entry": { "kind": "cut", "level": "high", "p0": [3.6, 14.2], "p1": [10.9, 6.8], "width": 3.8, "conf": 0.93 },
  "exit": { "kind": "cut", "level": "low", "p0": [40.1, 30.5], "p1": [31.2, 36.4], "width": 4.0, "conf": 0.88 },
  "left_joint": [3.6, 14.2],
  "right_joint": [40.1, 30.5],
  "source": { "file": "IMG_0142.jpg", "line": 7, "index": 12, "px_per_mm": null },
  "quality": { "cost": 0.8, "auto": true, "read": "и", "p": 0.99 },
  "enabled": true,
  "checked_by_user": true
}
```

- Координаты даны в пикселях PNG. `baseline` — линия строки; она берётся от всей строки, а не от буквы. `x_height` — высота строчных букв в исходной строке, по ней масштабируются все буквы.
- `entry` и `exit` — вход и выход пера. `p0` лежит на средней линии штриха, к ней крепится соединение. `p1` — вторая точка того же штриха глубже в букве. Перо движется от `p0` к `p1` на входе и от `p1` к `p0` на выходе.
- `kind`: `cut` — стык измерен на настоящем соединении с соседней буквой, `end` — естественный конец штриха, `virtual` — назначен по правилу.
- `level`: `low` — соединение у строки, `high` — у верха строчных (так выходят «о», «в», «ь», «ъ», «ю», «б»).
- `position` — где буква стояла в слове. При наборе предпочитаются варианты из такого же места и с такими же соседями.
- `quality.read` — что прочитал распознаватель в отдельно вырезанной букве.
- Поля `bbox`, `baseline`, `left_joint`, `right_joint` совпадают со старым форматом.

## Как устроено

| Часть | Что делает | Где |
|---|---|---|
| Анализ страницы | Карта чернил, наклон листа, линовка, строки, базовая линия и высота строчных | `src/core/analyze/page.ts` |
| Строка | Выравнивание строки, отделение соседних строк, наклон письма | `src/core/analyze/strip.ts` |
| Возможные границы букв | Промежутки и места, где наклонная линия пересекает один тонкий штрих | `src/core/analyze/segment.ts` |
| Распознавание | Чтение слов, вероятности букв по кадрам | `src/core/ocr/ctc.ts` |
| Привязка текста | Раскладка известного текста по кускам строки | `src/core/analyze/align.ts` |
| Буквы | Вырезание по скелету штриха, прозрачность, точки входа и выхода | `src/core/analyze/glyph.ts` |
| Проверка | Повторное чтение каждой буквы отдельно | `src/core/harvest.ts` |
| Набор | Выбор вариантов, соединения пером, нажим, построчная отрисовка | `src/core/synth/engine.ts` |
| PDF | Страницы из прозрачных растров строк | `src/core/pdf.ts` |
| Интерфейс | Три вкладки; вся обработка в отдельном потоке | `src/app`, `src/worker` |

Геометрия считается в OpenCV (сборка OpenCV.js). Распознаватель — модель `ai-forever/ReadingPipeline-notebooks` (CRNN с CTC, обучена на русских и английских школьных тетрадях), запускается через ONNX Runtime. Файл модели в репозитории не хранится: при сборке его скачивает `tools/fetch-model.mjs` и сверяет контрольную сумму.

Каждая строка текста отрисовывается отдельно в прозрачный растр и вставляется в PDF как изображение с маской прозрачности, поэтому память на телефоне расходуется в размере одной строки.

## Что проверено и чего пока нет

- Ядро покрыто тестами (`npm test`). Среди них проверка базовой линии на синтетической странице с известным ответом: отклонение меньше 0,1 высоты строчной буквы.
- Весь путь «фото → буквы → библиотека → предпросмотр → проверка чтением → PDF» пройден в браузере Chrome на образце из трёх строк.
- Автоматическое разрезание слитного письма ошибается: на образце низкого разрешения проверку повторным чтением прошло около 60 % вырезанных букв. Остальные показываются как сомнительные, их можно принять вручную.
- Ручного редактора границ букв и точек соединения пока нет: неудачную букву можно только не брать или исправить ей подпись.
- Сборка APK идёт в GitHub Actions; на реальном телефоне приложение не проверялось.
- Переносов слов нет: слово целиком уходит на следующую строку.
- Распознаватель не знает некоторых символов (например, «Й», «Ъ», `%`, `«»`); такие буквы принимаются только по совпадению чтения.

## Сборка

```bash
npm run typecheck   # проверка типов
npm test            # тесты ядра
npm run build       # сборка в dist/
npm run android     # сборка и обновление Android-проекта (нужен Android Studio)
```

Для APK на своём компьютере: `npm run model && npm run build && npx cap add android && npx cap open android`.
